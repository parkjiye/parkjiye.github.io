고객 시나리오별 앱푸시 자동 발송

2026.04 — 2026.06

배경

기존 앱푸시는 운영자가 매번 대상 고객을 직접 추려 솔루션 콘솔에서 수동 발송하는 방식이었음. 특정 조건(쿠폰 만료 임박, 입장 등)을 충족한 고객에게 자동 발송하는 자동화·설정 기반 프로세스는 없어 이를 신규로 설계·구축.

설계 판단

시나리오마다 개별 배치를 등록하는 일반적인 접근 대신, 발송 조건·활성화 여부·문구·랜딩 링크를 TASK 테이블로 관리하는 설정 기반 구조를 채택. 새 시나리오가 늘어도 코드 변경 없이 확장 가능하도록 함.

구현

고객 행동 기반(Spring AOP 이벤트 발행)과 스케줄 기반(Spring Scheduler) 두 경로가 공통 Task 판단을 거쳐 발송되도록 구성.

안정성

발송 로직을 AOP 이벤트로 분리해 기존 결제·입장 로직에 영향이 없도록 했고, Scheduler에 shedlock을 적용해 다중 인스턴스 환경에서의 중복 발송을 방지.

결과

운영자 수동 발송 → 조건 충족 시 자동 발송으로 전환. 신규 시나리오 추가 시 배치 개발·배포 없이 테이블 설정만으로 처리하고, 마케팅 부서가 개발 요청 없이 발송 활성화·시간·문구·링크를 직접 제어. [운영 중 시나리오 N개 / 누적 발송 N건 — 수치 확인 후 기입]

사용 기술

  • Java
  • Spring Boot
  • Spring AOP
  • Spring Scheduler(shedlock)
  • MSSQL
